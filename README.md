# Конкурентные переводы: круговой денежный поток без блокировок

В высоконагруженных системах (банки, криптобиржи, игровые экономики) блокировки (`synchronized`) могут стать узким
местом: они снижают параллелизм и рискуют вызвать deadlock. Альтернатива — **неблокирующая синхронизация** на основе *
*атомарных операций** и **CAS (Compare-and-Swap)**. В этом задании вы реализуете систему, где N пользователей *
*одновременно переводят деньги друг другу по кругу**, используя только `AtomicInteger` и `AtomicReference`. Это
упражнение научит вас проектировать потокобезопасные структуры **без блокировок**, понимать семантику CAS и избегать
типичных ошибок вроде ABA-проблемы или потери обновлений.

## **Описание Задачи**

Реализуйте многопоточную систему, в которой **N пользователей** образуют **круг**: каждый переводит фиксированную сумму
следующему пользователю (последний — первому). Все переводы происходят **одновременно и конкурентно**, но **без
блокировок** — только с использованием атомарных типов.

* **Основная функциональность**
    * Создайте класс `User`, представляющий участника системы:
        - баланс хранится в `AtomicInteger`;
        - у каждого пользователя есть ссылка на **следующего** в круге.
    * Реализуйте операцию **перевода**:
        - пользователь пытается списать сумму `X` со своего счёта;
        - если средств достаточно — добавляет `X` к балансу следующего;
        - если недостаточно — пропускает перевод в этом цикле.
    * Каждый пользователь — **отдельный поток**, который в бесконечном цикле пытается сделать перевод случайному
      пользователю
    * Система должна работать **минимум 5 секунд**, после чего завершиться и вывести:
        - начальный и конечный общий баланс всех пользователей;
        - баланс каждого пользователя;
        - количество суммарного баланса;

* **Дополнительные условия / Ограничения**
    * **Запрещено использовать** `synchronized`, `ReentrantLock`, `volatile` (кроме как внутри атомарных типов) и любые
      блокировки.
    * Балансы **должны быть** `AtomicInteger`.
    * Операция перевода **должна быть атомарной** на уровне «списать → зачислить» — но без блокировок!  
      → Подсказка: можно использовать **попытки с CAS** или **атомарные обновления с предикатом** (`getAndUpdate`,
      `updateAndGet`).
    * Общий баланс **должен сохраняться неизменным** (никакой утечки денег!).
    * Все потоки запускаются одновременно и работают независимо.
    * Используйте только стандартные атомарные классы: `AtomicInteger`, при необходимости — `AtomicReference`.

* **Примеры использования**
    * **Пример сценария:**
        1. Создаётся 5 пользователей с балансом по 1000.
        2. Каждый пытается переводить по 10 единиц следующему.
        3. Запускаются 5 потоков.
        4. Через 5 секунд система останавливается.
        5. Вывод:
           ```
           Общий баланс: 5000 → 5000 ✅  
           Пользователь 0: 987  
           Пользователь 1: 1012  
           ...  
           Успешных переводов: 2450
           ```

-----

## Входные / Выходные данные (если применимо)

* **Вход:**
    - Количество пользователей (`N ≥ 2`),
    - Сумма перевода (`X > 0`),
    - Время работы (5 секунд — фиксировано).

* **Выход:**
    - Начальный и конечный общий баланс (должны совпадать);
    - Баланс каждого пользователя;
    - Статистика по переводам.

* **Критерий корректности:**  
  **Сумма всех балансов не должна измениться** за время работы.

-----

## Технические требования

* Используйте `AtomicInteger` для баланса.
* Для остановки потоков — флаг `volatile boolean running` (это допустимо, так как он не защищает разделяемое состояние,
  а только управляет жизненным циклом).
* Не используйте `Thread.sleep()` внутри критической логики перевода.
* Все операции перевода — через атомарные методы (`compareAndSet`, `updateAndGet` и т.п.).
* **Среда выполнения:** Консоль
